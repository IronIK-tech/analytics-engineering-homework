# Практична робота: конвеєр курсів валют НБУ у BigQuery

Щоденний конвеєр даних у Google BigQuery: курс гривні з відкритого API НБУ
записується сирим у шар bronze, з нього будуються виміри, снепшот поточних
курсів та історична таблиця фактів. Запуск шести ноутбуків координує
ноутбук-оркестратор.

Джерело: `https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json`

## Архітектура

| Датасет   | Шар    | Що містить                                  |
|-----------|--------|---------------------------------------------|
| `nbu_raw` | bronze | сирі відповіді API як є                     |
| `nbu_dwh` | gold   | виміри, снепшот, таблиця фактів             |
| `nbu_meta`| мета   | журнал запусків оркестратора                |

Усі датасети в регіоні EU.

## Ноутбуки

| Ноутбук                 | Таблиця                         | Зерно                       | Стратегія запису |
|-------------------------|---------------------------------|-----------------------------|------------------|
| `01_bronze.ipynb`       | `nbu_raw.raw_rates`             | один об'єкт відповіді API   | append           |
| `02_dim_currency.ipynb` | `nbu_dwh.dim_currency`          | одна валюта                 | truncate         |
| `03_dim_date.ipynb`     | `nbu_dwh.dim_date`              | одна доба                   | truncate         |
| `04_snapshot.ipynb`     | `nbu_dwh.snapshot_rates_current`| одна валюта                 | truncate         |
| `05_fact_merge.ipynb`   | `nbu_dwh.fact_exchange_rate`    | валюта × доба               | merge            |
| `00_run_all.ipynb`      | `nbu_meta.run_log`              | один запуск одного ноутбука | append           |

Порядок виконання: 01 → 02 → 03 → 04 → 05. Тільки ноутбук 01 звертається до API,
решта читають дані зі сховища.

## Три стратегії запису

- **Append (01, журнал у 00):** дані тільки дописуються. Повторний запуск
  навмисно дублює рядки; `payload_hash` (MD5 від JSON) показує, що зміст той самий.
  Дублікати в bronze не чистяться, це нормальна поведінка журналу завантажень.
- **Truncate (02, 03, 04):** таблиця щоразу перезаписується з нуля, результат
  ідемпотентний.
- **Merge (05):** SQL `MERGE` оновлює або додає лише поточну дату за ключем
  `date_key + currency_key`, історія не чіпається. Повторний запуск не створює
  дублікатів.

## Особливості реалізації

- **Дата для злиття.** НБУ публікує курс наперед: у відповіді `exchangedate`
  може бути наступним робочим днем. Тому в `05_fact_merge.ipynb` замість
  `business_date = CURRENT_DATE()` береться остання дата в bronze
  (`MAX(business_date)`), інакше вибірка була б порожньою.
- **Рядки Unknown.** У `dim_currency` (`currency_key = -1`) і `dim_date`
  (`date_key = -1`) є службовий рядок для невідомих значень.
- **MERGE.** Проєкт має повноцінний доступ до DML (не Sandbox), тому
  використано спосіб А (SQL `MERGE` через проміжну таблицю `_stg_rates_today`).
- **Оркестратор.** Запускає ноутбуки через `papermill`, зупиняється на першій
  помилці, пише журнал (`run_id`, `step_no`, `notebook`, `status`,
  `started_at`, `finished_at`, `duration_sec`, `error`) у `nbu_meta.run_log`.
  Копії виконаних ноутбуків лежать у `runs/` (не входить у репозиторій).

## Запуск

1. Встановити залежності:
```bash
   pip install google-cloud-bigquery pandas pyarrow db-dtypes requests papermill jupyter
```
2. Авторизуватися (неінтерактивно, потрібно для дочірніх ядер оркестратора):
```bash
   gcloud auth application-default login
```
3. У першій комірці кожного ноутбука вказати свій `PROJECT_ID`.
4. Запустити ноутбуки 01-05 по черзі або відкрити `00_run_all.ipynb` і виконати його.

Ключ сервісного акаунта в репозиторій не потрапляє (`*.json` у `.gitignore`).

## Перевірки

- 01: після двох запусків за одну дату `rows_cnt` подвоюється, `uniq_cnt` не змінюється.
- 02: `currency_code` унікальний, є `currency_key = -1`.
- 03: календар без пропусків, є `date_key = -1`.
- 04: рядків стільки, скільки валют у bronze, немає `currency_key = -1`.
- 05: зерно `date_key + currency_key` унікальне, повторний запуск не змінює
  кількість рядків.
- 00: TODO: описати результат тесту зі зламаним ноутбуком (статус `FAILED`,
  наступні ноутбуки не запускаються).
